# 循迹车 PID 上位机

双击 `启动上位机.command`。本机已经安装运行所需的 uv；首次启动会准备 PySerial 3.5。界面地址为 <http://127.0.0.1:8765/>。已运行时再次双击会打开现有界面。

其他电脑可安装 Python 3.10 以上，然后执行 `pip install -r requirements.txt`、`python app.py --open`。该启动方式未在 Windows 实机验证。

## 使用

1. 选择 `SEEKFREE Wireless Com Port` 对应的 USB 串口，波特率 115200，连接。
2. 点击“读取车端参数”。灰色提示值只来自源码，车端回复后的数值才是实际参数。
3. 修改一个参数，点击该行“发送”。显示“车端已确认”才代表固件接受了写入；“等待”或“未确认生效”不代表成功。
4. 观察目标/左右轮速度、目标/实际角速度，以及 PWM 命令波形。可暂停显示、切换时间窗、隐藏曲线、导出 CSV。
5. 参数草稿可以保存/载入 JSON；载入草稿不会自动向车辆发送。

当前速度环两轮共用 `KP_L / KI_L / KD_L`。固件中的 `KP_R / KI_R / KD_R` 没有参与计算，因此界面没有把它们当成独立右轮 PID。

页面不自动启动车辆。“发送停车指令 !”需要车端回复，并应结合 PWM 波形归零判断；断开串口本身不会让车自动停车。

## 转向表与巡航速度

原表在 `app_adc.c` 中：弯号 7、8、11、14；角度 -75、-25、20、20；出弯确认时间 100、100、600、10。

“临时停用转向表”逐项将 `turn1` 到 `turn20` 设为 0，保留角度和出弯时间。固件用弯号 0 表示空槽。每项都需要车端确认，正常传感器/PID 循迹保留。这些串口修改只在当前 RAM 中生效，车辆断电或复位后会恢复正在运行的固件默认值。

当前已经烧入主板的新固件 `firmware-fix/Table-off-speed40-F407VE.*`：源码中默认巡航速度为 40，`TURN_FORCE_TABLE_ENABLED=0` 禁用查表；原表内容仍保留。将这个源码开关改为 1，可重新启用查表。

`firmware-fix/PID-link-fix-F407VE.*` 是此前烧入主板的调度与停车修复版，当前新版在此基础上增加默认速度 40 与关闭转向表。它保留原有 PID 公式和 29 通道串口协议，将阻塞 SPI 采集移到主循环，控制 ISR 使用完整快照；停车分支将 PWM 归零。`before-PID-fix-512KB.bin` 是烧录前整片 Flash 备份。

## 数据含义与验证范围

实际固件发送 **29 个整数通道**，虽有旧注释写成 28。本工具按真实 `snprintf` 字段顺序解析。CH0–3 除以 100，CH12 除以 10；14 路传感器字段为二值状态，不能用来判断原始 ADC 幅值或已完成校准。

波形时间轴是电脑接收时间。当前实测约 15 Hz，能够观察较慢变化；它不是 1 kHz 控制环每一步的完整记录。CSV 最多保留最近 18000 帧，服务关闭后内存记录会丢失，请及时导出。

实车已验证：读取 12 个界面参数，将 KP_L 从 25 改为 25.125 并恢复为 25，两次均收到车端确认，随后查询再次读回 25。记录见 `validation/live-validation.json`。停车 PWM 和计时恢复也做过寄存器检查。光学标定、PID 是否合适、赛道运行及界面视觉效果仍需操作者验收。

已验证 ST-Link 与电脑侧无线 USB 接收器可以同时连接。此前接回 ST-Link 时，无线接收器曾从 USB 设备列表消失；两个 USB 设备都保持连接后，主板收到了完整命令，电脑也收到了确认。不能把接收器缺失误判为 ST-Link 与串口必然冲突。

服务只监听 127.0.0.1；不会上传车辆数据。程序断线后会如实显示状态，重新插好设备后刷新串口并连接即可。请勿让 VOFA+ 等软件同时占用同一串口。

## 14 路传感器权重

界面下方的权重卡片对应车端 S01–S14，分别发送 `weight1` 到 `weight14`。取值为非负幅值 0–100，左右符号仍由原扫描算法决定。默认从 S01 到 S14 为 6.5、5、4、3、2、1、0.1、0.1、1、2、3、4、5、6.5，与原来的 7 组镜像权重完全等价。

点击“读取权重”，收到全部 14 个车端参数后才解锁输入；支持逐路或批量发送，保存/载入草稿也包含权重。旧固件没有这些命令，界面会保持未就绪，不会声称修改生效。

在左右对应传感器同时命中时，独立权重计算右侧归一化读数 × 右权重减去左侧读数 × 左权重；镜像权重相同时使用原表达式以保持默认行为。扫描顺序、标定、平均滤波和 PID 公式保留。外側优先级仍保留，权重 0 并不改变扫描优先级。

新增固件在 `firmware-fix/sensor-weights/`，已烧入主板并完成整段回读校验。14 路参数全部通过串口读出；第 7 路由 0.1 改为 0.15，再恢复为 0.1，均获车端确认，第 8 路始终保持 0.1。原先的 KP_L=70、巡航速度=50 等本次上电设置已恢复。记录见 `live-serial-validation.json`。重烧后仍需重新进行光学标定和实车验收。默认等价性有 10500 个 C 主机测试用例通过，串口及输入验证测试共 7 项通过。实际烧录和写入回读结果以该目录验证记录为准。

## 连续录制与分析

连接串口后点击“开始录制”，可填写本次测试说明。录制连续写入 recordings/，不受显示缓存 18000 帧上限限制。点击“停止录制并保存”会封存会话并生成 ZIP，可重新下载；停止录制不会停止车辆。

ZIP 包含 frames.csv（29 路原始字段与换算值、接收时间、单调时钟相对时间）、serial-rx.bin（全部接收字节）、serial-tx.bin（实际发送字节）、serial-chunks.jsonl（字节偏移与接收/发送时刻）、events.jsonl（参数回复、改参和连接/错误事件）及 manifest.json（端口、参数快照、通道定义、数据范围）。

停止后将 ZIP 发到聊天即可分析；在同一台电脑上，也可直接告诉助手录制会话编号，让助手读取本地文件。程序不会自动把文件上传到聊天或外部服务。

录制只覆盖固件实际发送的串口数据。当前是 29 列、约 15 Hz，14 路传感器是二值状态；不是原始 ADC，也不是控制环全部 1 kHz 采样。开始前可手动读取一次参数，使快照更完整，未查询或较早确认的参数会保留其时间戳，而不会假装是当前值。

断线会留下事件和数据间隙，重连后继续录制，不插入虚构数据。文件每秒刷新；正常关闭服务会尝试封存录制。如果进程或电脑意外中断，保留下来的会话目录可用于恢复分析，但可能没有 ZIP，manifest 中会标记未完成。

## 转向表编辑

连接串口后点击“读取转向表”，收到全部 20 行和进弯确认时间才开放编辑。每行有弯号（0 为空）、转角（度，正右负左）、出弯确认时间（ms）。可写入单行或整表，逐项收到 `[OK]` 才标为车端确认；失败会取消剩余队列，不应认为整表成功。整表写入不是原子事务，可再次读取核对。保存/载入参数草稿包含表格；录制包含其读取、写入及确认记录。

新版主板固件提供独立 `turn_enable=0/1` 开关（复位默认 0）。先读取车端参数；收到 `turn_enable` 才开放独立开关，页面只按车端回复显示状态。旧固件没有该参数，需要重烧。开启前上位机要求完整读取前 5 槽配置，并收到最近 2 秒内的停车状态波形；关闭可在运行中发送。关闭立即取消当前强制转向，保持弯道计数和整张表；开启从下一次新进弯起按弯号查表。实际仅处理前 5 槽；6–20 备用。“清零全部弯号”仍是独立清表动作。修改仅保存在 RAM，复位恢复默认值；开关不包含在草稿或整表写入中。录制会保留开关命令及确认记录。
